What crossing the spread actually costs

Every headline number in this project so far assumes a maker fill: a resting limit order that earns $0 fee plus a rebate because it provides liquidity rather than consuming it. This models the other case — a taker order that has to cross the spread — using real price‑impact measured from actual trade prints, not an assumed slippage percentage.

The 70% threshold: real costs don't just shrink the edge, they erase it

The looser 70% entry threshold looked like the standout performer earlier in this project — more signals, higher raw CAGR, more compounding cycles. It's exactly those properties that make it far more exposed to real execution costs, not less: at 70% the market hasn't converged yet, so real order flow has to move price meaningfully to fill a position, instead of the near‑certain, already -settled liquidity near 99%.

Notice the shape, not just the endpoint: the taker+slippage curve doesn't decline gently, it falls to roughly $4,060 (a 59% drawdown) before recovering to just under the $10,000 starting bankroll. Checked directly rather than left as a surprising number: no single trade drives this — every one of Kelly's worst losses is capped at the pre‑existing 3%‑of‑equity position limit, around $300–$327 each. What actually happens is aggregate cancellation across 1,802 taken trades: total dollars won ($54,171) and total dollars lost ($54,258) land within 0.16% of each other. At 70% the true win rate is only ~87.5% (vs. 99.9%+ at 99%), so the per‑trade margin was already thin; shaving 1–2.5% off every entry price plus a real taker fee doesn't need to be catastrophic on any one trade to erase a thin aggregate edge across thousands of trades — it just needs to shrink total wins down to roughly match total losses, which is exactly what happened.
An honest limit on precision here: only 21.8% of these trades had real BUY‑side prints to measure slippage from. The other 78.2% are priced using the population mean (2.48%, pulled up by a fat right tail) as a fallback, not a per‑trade measurement. If the true typical cost for those unmeasured trades is closer to the median (1.55%), the drawdown would likely be less severe — probably still a near‑complete erasure of the maker‑fill edge at this threshold, not a rounding difference, but the exact $4,060 low shouldn't be read as more precise than the data underneath it actually is.

The broader lesson isn't "70% is worse than 99%" in the abstract — it's that the more trades and the more aggressive the sizing, the more a strategy's real‑world viability depends on actually achieving passive maker fills, since that is exactly where the maker‑fill dependency is most expensive to get wrong.

Reading this honestly

The 86% of trades with no measurable slippage data aren't neutral — they're systematically the quieter moments, which likely means thinner liquidity and probably worse real impact than what's measured here, not better. This estimate should be read as a floor on real execution cost, not a ceiling.

The maker-fill dependency is the real risk, not slippage itself. If you can reliably rest limit orders and get filled passively, the $0-fee maker numbers throughout this project stand. If real deployment requires taking liquidity on demand — because a resting bid at the right price doesn't get hit in time, or the position needs to go on now — the realistic edge is closer to the right-hand curve above: still positive, roughly half the headline Sharpe, not the number this whole analysis has been built around.

Reading this correctly. This is a historical backtest on resolved Polymarket markets, not a live track record. The VWAP walk uses realized trade prints as a proxy for order- book depth, the same limitation as every fill-price estimate elsewhere in this project — a real historical order book doesn't exist for resolved markets.
