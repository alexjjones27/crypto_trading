What crossing the spread actually costs

Every headline number in this project so far assumes a maker fill: a resting limit order that earns $0 fee plus a rebate because it provides liquidity rather than consuming it. This models the other case — a taker order that has to cross the spread — using real price‑impact measured from actual trade prints, not an assumed slippage percentage.

Corrected from an earlier version. The first pass measured "slippage" over a 5‑minute window with no guard against the market simply re‑pricing on new information — on one sports market it read an entry at $0.71 followed by a real print at $0.98 89 seconds later (the game had resolved in between) as 38% slippage, when it was actually the market correctly updating, not an order consuming liquidity. Fixed by shrinking the window to 20 seconds and stopping the walk the moment a print lands more than 3¢ from the entry price. The numbers below are the corrected ones; see the data‑integrity section further down for the full account.

Same recommended quarter‑Kelly configuration (3% per‑trade / 50% aggregate / 25% per‑category caps), same 2,367‑trade population, same $10,000 start — the only difference between these two curves is whether the fill is a passive maker order or an aggressive taker order paying the real fee and the real, measured price impact.

Slippage scales with liquidity, the way it should

Measured, not assumed: trades grouped by realized trading activity (shares/minute) in the same 20‑second window used for the fill estimate itself. The pattern is exactly what real market microstructure predicts — thinner liquidity, worse average price impact.

The 70% threshold: real costs cut deep, but don't erase the edge

The looser 70% entry threshold looked like the standout performer earlier in this project — more signals, higher raw CAGR, more compounding cycles. Real execution costs bite harder here than at 99%: at 70% the market hasn't converged yet, so real order flow moves price more to fill a position than it does near the already‑settled liquidity close to 99%.

The taker+slippage curve carries real drawdown risk on the way there — a genuine 44.9% max drawdown (vs. 28.6% for the maker baseline at this same threshold), bottoming around $5,596 in November 2025 before recovering and continuing to climb to $21,620. This is a meaningfully rougher ride than the maker -fill numbers this whole project is built around, but it is a real, surviving edge — 2.16× the starting bankroll, not the near‑total erasure an earlier, buggy version of this model reported.
An honest limit on precision here: only 6.8% of these trades had real BUY‑side prints within the tight 20‑second window to measure slippage from — a real cost of fixing the informational -repricing bug, since a shorter window means fewer trades have any qualifying print at all. The other 93.2% are priced using the population mean (0.90%) as a fallback, not a per‑trade measurement.

The broader lesson isn't "70% is worse than 99%" in the abstract — it's that the more trades and the more aggressive the sizing, the more a strategy's real‑world viability depends on actually achieving passive maker fills, since that is exactly where the maker‑fill dependency costs the most in both directions: most Sharpe lost here, but still the larger raw edge even after paying it.

Reading this honestly

The vast majority of trades (97.6% at 99%, 93.2% at 70%) have no measurable slippage data within the tight 20‑second window this model now requires. They aren't neutral — they're systematically the quieter moments, which likely means thinner liquidity and probably worse real impact than what's measured here, not better. This estimate should be read as a floor on real execution cost, not a ceiling. The tight window is itself a deliberate tradeoff: a wider one would measure more trades but re‑introduce the informational‑repricing conflation this version was built to fix (see the correction note at the top of this page).

The maker-fill dependency is the real risk, not slippage itself. If you can reliably rest limit orders and get filled passively, the $0-fee maker numbers throughout this project stand. If real deployment requires taking liquidity on demand — because a resting bid at the right price doesn't get hit in time, or the position needs to go on now — the realistic edge is closer to the right-hand curve above: still positive, roughly half the headline Sharpe, not the number this whole analysis has been built around.

Reading this correctly. This is a historical backtest on resolved Polymarket markets, not a live track record. The VWAP walk uses realized trade prints as a proxy for order- book depth, the same limitation as every fill-price estimate elsewhere in this project — a real historical order book doesn't exist for resolved markets.
