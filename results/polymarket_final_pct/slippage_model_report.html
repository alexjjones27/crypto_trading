What crossing the spread actually costs

Every headline number in this project so far assumes a maker fill: a resting limit order that earns $0 fee plus a rebate because it provides liquidity rather than consuming it. This models the other case — a taker order that has to cross the spread — using real price‑impact measured from actual trade prints, not an assumed slippage percentage.

Slippage scales with liquidity, the way it should

Measured, not assumed: trades grouped by realized trading activity (shares/minute) in the same 5‑minute window used for the fill estimate itself. The pattern is exactly what real market microstructure predicts — thinner liquidity, worse average price impact.

Reading this honestly

The 86% of trades with no measurable slippage data aren't neutral — they're systematically the quieter moments, which likely means thinner liquidity and probably worse real impact than what's measured here, not better. This estimate should be read as a floor on real execution cost, not a ceiling.

The maker-fill dependency is the real risk, not slippage itself. If you can reliably rest limit orders and get filled passively, the $0-fee maker numbers throughout this project stand. If real deployment requires taking liquidity on demand — because a resting bid at the right price doesn't get hit in time, or the position needs to go on now — the realistic edge is closer to the right-hand curve above: still positive, roughly half the headline Sharpe, not the number this whole analysis has been built around.

Reading this correctly. This is a historical backtest on resolved Polymarket markets, not a live track record. The VWAP walk uses realized trade prints as a proxy for order- book depth, the same limitation as every fill-price estimate elsewhere in this project — a real historical order book doesn't exist for resolved markets.
